## 命令行参数

所有运行命令共用 `cold-world-game` 根入口：`game` 启动游戏，`test` 进入[测试命令](../development/development.md#测试入口)。根命令和未指定具体测试的 `test` 只显示帮助，不创建存档、不启动服务或压力测试。

`uv run cold-world-game game` 与 `uv run python -m cold_world_game game` 等价；`uv run cold-world-game game --help` 查看下表参数。Windows PowerShell 和 Linux shell 使用相同参数，不需要平台专用启动脚本。

| 参数 | 默认值 | 用途 |
| --- | --- | --- |
| `--host` | `127.0.0.1` | 监听地址，局域网联机用 `0.0.0.0` |
| `--port` | `5000` | 0～65535；0 表示自动分配，终端输出实际端口 |
| `--password` | 每次启动随机生成 | 共享游戏口令，不允许空字符串；固定口令须显式传入 |
| `--admin` | 不启用玩家管理员 | 唯一管理员玩家 ID；只对本次启动生效，见 [管理员命令手册](admin.md) |
| `--save-path` | `~/.cold-world-game` | 存档目录或 `.db` / `.sqlite` / `.sqlite3` 文件路径 |
| `--seed` | 新世界随机种子 | 只影响新建世界；加载已有存档时保留原种子 |
| `--allowed-origin` | 仅同源 | 可重复添加允许连接的额外浏览器 Origin，不是访问口令 |
| `--log-level` | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |

```sh
uv run cold-world-game game --host 0.0.0.0 --port 5000 --password your-server-password --save-path ./saves --log-level INFO
```

## 连接与离线

浏览器访问服务器网页并输入玩家ID和共享口令。未传入 `--password` 时每次启动生成新的随机口令，输出到终端，不保存到世界。浏览器可缓存上次填写值，各窗口的连接身份独立；不同ID可以同时在线，同ID不允许抢占已有连接。

新玩家在原点建筑区块的随机可落脚位置出生，初始体温36°C、饥饿10，携带手枪、斧头和打火机。再次登录恢复原状态，不重复发初始装备。离线时保存坐标、背包/物品栏、剩余弹药与次数、生存值和状态，立即移除地图人物，不参与碰撞、索敌或伤害。

个人离线期间所有个人数值冻结，不消耗也不恢复；若仍有其他玩家在线，世界和已放置篝火继续运行。全员退出后整个世界暂停，怪物保留原位，不生成或清除，不推进日期、燃烧与子弹。停机同样不补算时间。重连原位置被障碍占用时只修正到附近最近合法位置，木地板可落脚。

玩家列表使用真实登录时间而不是游戏时钟，离线持续多久照常显示。各界面的详细操作见[操作手册](../guide/controls.md)。

## 登录位置与座位

离线角色不留在地图上，也不保留公园椅子或固定机枪的占座。重新加入时，若上次位置是座位或已被障碍/实体占用，选择距原位置最近的可落脚空格，木地板与地雷可作为落脚地面，不拆除或移动已有建筑。固定机枪剩余弹药随世界保存，不因玩家重连或服务端重启补满；详见[户外设施](../building/outdoor-facilities.md)。

## 进程与部署

Windows与Linux采用相同Python包及uv依赖管理，内置Flask网页和同源WebSocket，无需另启前端服务。服务器单进程、一个世界，使用带线程的Werkzeug服务；不要配置多个WSGI worker、开发自动重载或多个进程打开同一存档。

默认只监听本机；局域网用 `--host 0.0.0.0`，浏览器访问服务器实际IP与端口，不是0.0.0.0。公网应由HTTPS/WSS反向代理加连接限制。额外浏览器Origin须通过 `--allowed-origin` 显式允许，不等于游戏口令。

本项目面向可信私人联机，不提供移动速度反作弊；浏览器算本机移动，服务端统一怪物、伤害、冷却和物品事务。共享口令不是各玩家ID的独立所有权证明，管理员ID也应仅告知可信人员。启动管理员、英文命令和错误见[管理员手册](admin.md)。

## 保存与故障处理

物品转移、制作、交易、使用、拆除掉落、金币与伤害先在世界锁内原子结算，成功后确认并发布事件；校验失败整次回退。**确认表示服务器内存已完成操作，不表示已经落盘**。服务器按一致性快照合并多次操作，由单独线程在SQLite事务中保存；背包、容器、地面、金额、实体和随机状态来自同一个快照，恢复后不会留下半次转移。WAL与 `synchronous=FULL` 保持开启。

正常每15秒检查保存，繁忙时延到约60秒；持续高负载时最迟在未保存约150秒发起强制保存，预留提交时间。以现实单调时间计时，不依赖游戏时钟。全员离线和正常停服强制保存。正常磁盘条件下不让未提交进度超过3分钟；如果提交迟迟不能完成，达到180秒就暂停新操作与模拟，而不是一边保存失败一边无限接受变更。单个玩家离线不要求其他在线玩家一起等待写盘。

后台写盘期间，游戏继续使用内存状态，新变化留给下一份快照；不会为每次开枪、命中、拾取或转移同步等待磁盘。代价是断电、强制结束进程或系统崩溃可能丢失最近未提交的一段进度，回到上次完整提交。不要把操作确认当作断电安全证明。

世界状态按名称分区保存在 `world_parts`。可确定性重建的自然地形只保存生成配置和区块清单，改变后才按实体ID保存覆盖或删除标记；玩家建筑及无法重建的旧区块保留实际记录。容器取放、机枪弹药和采集状态也属于覆盖，不会重启补满。保存和回滚只处理变化对象，建筑增删不重写全图ID索引，普通战斗不编码全部静态建筑。存储格式兼容读取旧格式，正常提交后使用稀疏格式；不需要删库或换地图。机制见[确定性地图](../development/terrain.md)，运行效率见[实时性与性能](../development/performance.md)。

后台写盘失败时，SQLite整次回退，保留完整待保存批次并重试；不把已经确认的内存操作逐条撤销。连续失败3次或超过180秒未完成保存时暂停世界，并记录错误；保存恢复后解除这个存储暂停，不清除其他模拟故障。检查磁盘空间、权限和设备，不要盲目重复发送消费命令，也不要删除世界或存档锁。`/health` 的 `persistence` 提供保存模式、未提交时间、失败次数与错误。

按Ctrl+C后停止接受新命令、断开连接并停止模拟/发布线程，再等待最终快照提交及保存线程退出，最后关闭数据库和释放存档锁。成功终端会出现 `Final world snapshot committed` 与 `Final world snapshot saved. Server stopped.`；失败会输出 `FINAL SAVE FAILED` 并以非零状态退出，不能当作已保存。请等待退出后再关闭终端；任务管理器强杀、`kill -9` 和断电无法执行最终保存。

## 备份与更新

1. 在终端按Ctrl+C，等正常保存退出。
2. 备份整个存档目录。运行中不要只复制主数据库而遗漏WAL；优先停服后备份。
3. 更新程序并执行 `uv sync --frozen`，使用相同的 `--save-path` 启动。
4. 用原玩家ID核对位置、物资、旧建筑与箱子，到尚未生成区域探索当前内容，再保存重启核对不重复生成。

不删除存档，不换种子，不重建旧区块；旧区域、箱内物品、被采集状态与玩家修改保持原样。未探索区块始终用当前生成规则，详见[地图与存档](../world/world.md#地图生成与存档)。

## 持久字段与缺省值

已有整图JSON和分区SQLite均可读取，首次保存可在事务内整理结构，失败保留原内容。世界种子、实体/物品ID、建筑顺序、区域标记和已有剩余次数不改变。缺省仅补不存在的字段，不把已经用过的物品补满。

| 数据 | 缺失时行为 |
| --- | --- |
| 生成配置与稀疏地图标记 | 旧存档保留完整原对象，未探索区块才建立当前生成配置；不从旧种子猜测并重建已有区块 |
| 玩家背包、金钱、登录时间、个人状态 | 空背包、0余额、未知登录记录、无状态；随身硬币按枚转入余额一次 |
| 容器共享余额 | 0，不改变其他内容 |
| 建筑弹药与放置者 | 旧存档固定机枪缺少弹药字段时按其原始200发读取；新生成机枪初始5000发；其他建筑无弹药；放置者缺省为空，不重置已保存的剩余弹药 |
| 物品弹药与次数 | 按对应物品初始定义补缺；已有数值原样保留 |
| 怪物冰冻、灼烧、临时重叠许可 | 无状态/无许可，不重置现有攻击冷却 |
| 怪物形态 | 缺省普通小怪，仍优先保留原大怪/快速怪标记、血量与位置 |
| 投射物可选来源、目标、命中记录 | 兼容缺省，保留保存的实体位置和速度 |
| 区块生成标记 | 已存在chunks按兼容起始标记读取，其他区块保持未生成 |

状态按世界运行时间或玩家在线时间恢复，停机不补算，不重复爆炸、掉落、刷箱或兑换。回退程序应同时恢复完整备份，不用较早程序直接写已经更新保存的数据库。接口字段见[协议手册](protocol.md)，开发检查见[开发维护](../development/development.md)。
