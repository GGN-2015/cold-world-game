## 配乐与实体预算

BGM仅在登录页预加载压缩音频，进入游戏取消未完成请求；战斗中不下载音乐，不在JavaScript主线程批量解码。威胁评分每0.5秒只遍历可见快照，原生双音频元素与Web Audio时间线负责交叉淡入淡出；开关、前后台或音频失败不改变模拟和通信频率。完整机制见[背景音乐](music.md)。

六种怪物共用寻路预算、按探索距离增长的总上限、位置历史与客户端平滑；上限公式及透视眼规则见[怪物生成](../world/combat.md#怪物生成)。总量判断通过对数比较实现，不直接求极大指数；透视眼仅在18:00～次日06:00追踪站立在线目标，远距离拆为局部路径，共用原有规划预算，不遍历或生成整条跨世界路线。昼夜变化时丢弃受影响怪物的旧追踪与规划，寻路任务也校验透视是否生效，避免跨时段回写旧路径。坐姿与机枪方向均使用预导出PNG。地雷维护专用索引，移动子步只检查所在格，不遍历整张地图；爆炸复用现有范围结算和共享PNG，不影响其他建筑。机枪弹药及占座继续走建筑字段差分，不序列化未变化的全部建筑。

本册解释本机响应、多人平滑显示和性能验证。游戏规则见玩法手册，消息字段见[协议手册](../server/protocol.md)，部署与存档维护见[服务器手册](../server/server.md)。

## 本机即时响应

浏览器逐帧计算自己移动、碰撞和沿墙滑动，约50毫秒汇总上报；攻击、放置和丢弃前立即上报最终位置与瞄准。服务器汇总本机位置，不重复积分；怪物、伤害、冷却、消耗和掉落仍统一结算。

近战点击立即选择预烘焙的八方向六帧PNG并播放挥动音效，不等待网络往返。服务器用attack_id确认本机预览，匹配事件不重复播放；拒绝/失败取消预览，预览不结算伤害。物品转移同样即时预览，按请求序号合并确认，失败整体回退，不在客户端创建权威物品。

## 多人和怪物连续显示

按实体ID保存最多32份位置样本，在约120～280毫秒自适应缓冲上插值；世界显示时钟缓慢校准，不因新包跳变。朝向和跑动帧使用实际显示位移，避免网络节奏控制动画步频。

短暂缺样用最近两份位置平均速度外推最多300毫秒，之后平滑减速，额外路程不超过约420毫秒的移动量；500毫秒无状态时远端冻结。本机超过1秒无状态停止，恢复不补跑后台时间。子弹有独立即时通道，不等待角色缓冲，断流300～500毫秒间减速停止。

普通位置误差连续消除，不因超过某个距离就瞬移；移动修正序号保护击退，显式teleport_epoch区分真正传送。远端普通行走速度不超自身当前速度；追赶修正有上限，高速手持装备也不会把误差修正成三倍猛冲。移除/死亡立即生效，重连、后台、暂停和真正传送重建适用轨迹。

## 战斗消息预算

浏览器协商紧凑二进制状态：短ID引用、字段编号与定点数减少反复出现的文本和高精度尾数；常规子弹只传首次可见的轨迹参数与最终移除，由客户端逐帧显示，服务端仍逐tick判定伤害、穿透和射程。重连和中途进入视野都有轨迹锚点，特殊追踪弹保留必要目标信息，不用客户端动画代替结算。

背包与容器只传变化格子，建筑动态外观按ID差分。新增战斗事件独立于活动实体生命周期，不再为过期特效发送删除列表；名单只更新改变的账号。浏览器合并同一绘制帧前的画面发布，但先顺序应用全部差分并保留新增事件；输入静止时用250毫秒心跳、移动时仍约50毫秒汇总，转屏与关键操作立即处理。协议细节见[紧凑状态传输](../server/protocol.md#紧凑状态传输)。

## 服务端时间预算

20Hz模拟、约10Hz世界同步，玩家名单独立约1Hz。寻路任务可暂停，轮转分批续算，每tick最多开始8个任务、共享约8毫秒搜索预算，普通批次约32个节点；封闭目标的候选格扫描也分批。已有合法路径继续移动，索敌、冷却与攻击不等待整次搜索完成。

静态建筑按实体ID保存脏数据与回滚记录，不在每次战斗复制或序列化全图。SQLite事务使用WAL及FULL同步，产出保存成功才确认；不能为降低延迟牺牲原子保存。未变建筑/背包不重复发，客户端复用静态碰撞网格、格子DOM及容器输入框。

## 绘制与资源预算

雪地纹理离屏缓存，按需重建；角色四方向差分、八方向武器刃光、受击/死亡/医疗/爆炸均离线生成PNG图集。怪物灼烧叠同一小火苗动画，不生成专属立绘或实时粒子。运行时只按时间选帧贴图，动画不驱动玩法。

音效按事件去重、距离衰减，避免重复快照产生音频风暴。资源替换见[美术](assets.md)与[音效](audio.md)，模块职责见[开发维护](development.md)。

## 回归场景

- 在实际往返约300毫秒的链路测试，而不是只在无延迟localhost测试；分别记录输入到本机画面、远端移动、服务器tick和绘制耗时。
- 大地图、多玩家同向同行、怪物达到当前距离对应的上限并持续战斗，同时覆盖70、140、280只及含透视眼的场景；重点观察普通移动是否突然跳位、拐角是否反复急停、斧头点击是否等待回包。测试行走时补怪不能意外落入清空的通道，以免将合法碰撞和击退误报为同步故障。
- 往返转移背包/物品栏/箱子，包含高延迟、满格、多人竞争、写盘失败；本机预览立即，最终物品与SQLite完全一致。
- 手机横屏、竖屏和方向锁定下测试摇杆、长按、容器操作；选物品不得强迫滚动到说明，窄屏说明默认折叠。
- 模拟断线、重连、后台再返回、击退、倒地、传送和停止服务器；普通同行不能被误当作传送，取消动作不能重放成消费。

排查时分别量测服务器模拟/寻路、SQLite提交、JSON编码/差分字节、DOM更新与Canvas绘制，不把所有卡顿归咎于网络。保留世界与存档，不通过减少已生成地图或清空建筑来让测试看似流畅。

## 实测基准

### 同帧战斗通信对照

`uv run python tools/benchmark_sync.py`在临时世界运行16人、70只持续补充的怪物、8把步枪与8把斧头，覆盖1,681区块和20,157个建筑。连续15秒权威战斗帧分别交给已有JSON字段差分与紧凑协议，交替计时，共2,384对增量样本；两边都使用种子地图，握手、地图与名单均计入总字节，不拿完整状态广播作对照。

| 指标 | JSON字段差分 | 紧凑战斗传输 | 变化 |
| --- | --- | --- | --- |
| 全部应用消息 | 56,619,129字节 | 6,572,272字节 | 减少约88.4% |
| 差分与编码平均耗时 | 1.890ms | 1.497ms | 减少约21% |
| 差分与编码P95 | 2.701ms | 2.102ms | 减少约22% |

处理计时不含公共快照构建、锁等待、浏览器或TCP/TLS头，不能当作FPS。夹具补充怪物、弹药和体温以持续施压；与真实游玩性能分开判断。可用`--capture path.json`导出一名玩家的握手、二进制消息及权威弹道，核对跨语言解码、修订连续性、事件和显示误差；记录中含临时测试角色，不读取玩家存档。

另在3,481区块、约43,520建筑中，经双向各150毫秒的TCP代理让16人战斗、建造、拆除并同向行走，握手确认启用紧凑协议。桌面和手机触屏模拟两个Edge客户端实际绘制，其余14个独立客户端同样解码二进制并执行操作。成功放置27次、拆除18次，16人各行走约20.1～20.3米；两个画面的绘制P95约2.0～2.2ms、帧间隔P95约20.1ms，斧头本机PNG首帧P95约19.1～19.3ms。持续跟踪的普通运动未出现单帧超过0.75米的非传送跳变，没有超过50ms的主线程长任务或浏览器运行错误。单机桌面/手机模拟不等同于实体手机性能，继续以同帧回放而非不同实时时长的总流量证明通信收益。

### 同图协议与存档对照

`uv run python tools/benchmark_terrain.py`在临时目录创建固定种子世界，不读取或修改玩家存档。两条路径使用**同一张地图、同一批玩家和怪物、同一路线**；原路径也启用已有实体差分，不拿完整快照广播作虚弱对照。每次测量包含快照、差分和JSON编码；串行执行排除世界锁排队，不把锁等待转移到另一个函数后误报为CPU优化。

Windows实测配置为16名玩家、70只怪物、1,681个区块、20,219个自然对象，每名玩家沿180米路线取120份状态，共1,920份样本。地图不清空建筑，数据库尺寸均在WAL检查点后读取：

| 指标 | 服务端地图/实体差分 | 种子基底/区块差分 | 变化 |
| --- | --- | --- | --- |
| 状态处理平均耗时 | 1.086ms | 0.450ms | 减少约59% |
| 状态处理P95 | 1.485ms | 0.803ms | 减少约46% |
| 地图相关通信 | 556,556字节 | 292,892字节 | 减少约47% |
| 全部状态通信 | 2,652,694字节 | 2,372,550字节 | 减少约11% |
| 同内容SQLite文件 | 5,656,576字节 | 102,400字节 | 减少约98% |
| 未改变自然对象的持久记录 | 每对象一条 | 0条 | 只保存基底配置与区块清单 |

首次握手的配置和区块摘要计入通信量；订阅切换与缓存冷启动也计入处理时间。这个回放不运行真实战斗或浏览器，不代表FPS；移动实体、背包、战斗事件仍需同步，因此不能把地图流量降幅说成全部通信的降幅。无法重建的旧区块仍保留完整存档，不享受此项数据库体积缩减。Linux下也验证相同算法、SQLite流程与16玩家回放可以运行。

### 十六人延迟与画面验证

另使用真实TCP代理，双向各延迟150ms，在3,481区块的大地图上让16名玩家与70只持续补充的怪物战斗，交错开枪、挥斧、放置和长按拆除。分别覆盖旧地图和可重建的新地图。为避免把同机显卡争用当作网络问题，常规画面测量使用桌面与手机触屏模拟两个Edge观察客户端，其余14个独立WebSocket客户端执行同类输入；全部16个连接都经过延迟代理，不用本地直连绕过压力。手机使用移动UA、触屏和横竖屏尺寸模拟，不将其等同于实体手机的硬件性能。

新地图实测约43,520个建筑，成功放置29次、确认拆除23次。两个观察客户端的绘制P95约2.1ms，画面间隔P95约20.1ms，斧头点击到本机PNG首帧P95约17.0～22.7ms，不等待网络往返。随后16人通过键盘、手机摇杆触屏事件或持续移动输入，在通道内同向前进20.1～20.3米；70只普通怪物继续追踪。持续跟踪的普通玩家与怪物运动未出现单帧超过0.75米的非传送跳变，未记录超过50ms的主线程长任务或JavaScript错误；怪物攻击、击退、伤害与SQLite原子提交仍开启。

探索增长上限另外覆盖140只持续补充的怪物，战斗阶段特意配置约10%的透视眼作为加压条件（实际自然生成概率为1%），仍为16连接、3,481区块和双向各150ms延迟。约53.7秒内成功放置28次、拆除21次；桌面/触屏观察端绘制P95分别约3.4/3.0ms，画面间隔P95均约30ms，挥斧首帧P95约27.8/29.4ms。16名角色同行约19.8～20.3米，持续跟踪实体未出现超过0.75米的非传送单帧跳变，没有超过50ms的主线程长任务或JavaScript错误。此场景验证同步和交互正确性，不将更高的刷怪上限等同于固定的帧率保证。

建造和同行使用专用空地/通道夹具，地图其他区域仍保留四万余对象；同图性能对照回放不清空建筑。负载夹具在体温过低时恢复测试角色，以持续施压，不把这种恢复当作游戏规则。注入的300ms只是链路延迟，繁忙时命令确认还可能包含服务端排队；本机PNG首帧与这个确认时延分开测量。

也运行16个完整浏览器实例同时渲染的压力场景，覆盖多人战斗、建造和拆除。单机同时承担16个Canvas会争用绘图资源，这种测试不能等同于16台独立设备；本方案不承诺消除显卡争用，也没有据此声称所有手机都稳定60FPS。同步正确性、地图带宽与每客户端帧率分别判定，不用总流量在不同时长场景中的差异证明收益。

### 缓存、兼容与交互回归

前后端对照729个含负坐标的区块，覆盖大整数种子、完整对象ID和外观；服务端另验证不同生成顺序下的箱内物品与物品ID完全一致。浏览器验证IndexedDB冷启动、命中、损坏修复、禁用存储、Worker失败回退，以及生成未完成时收到增删补丁、退订和重连的隔离。静态外观未变时，火光、占座和弹药更新不重建碰撞索引。

SQLite回归覆盖旧存储格式、旧区域和物品不变、未探索区域使用当前配置、删除标记、完整快照导入、覆盖恢复默认后剪枝、两次重启不重复生成、满格转移拒绝和真实写盘失败整次回滚。桌面/手机实际交互、方向锁定无关的横竖屏布局、摇杆、长按、容器、双语与173种HUD布局均单独验证。

这些数字是本机自动化测量，不是所有设备、地图规模与在线人数的性能保证。部署环境应沿用上述场景复测，并分别观察状态到达间隔、SQLite提交、主线程长任务和真正的画面停顿。
