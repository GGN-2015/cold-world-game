# 确定性地图与区块差分

[项目首页](../../README.md) · [手册总目录](../README.md) · [开发目录](README.md)

本册说明地图初始状态、权威修改、浏览器缓存和存档之间的关系。地图玩法见[世界手册](../world/world.md)，消息格式见[服务器协议](../server/protocol.md)。

## 三层状态

| 层次 | 内容 | 负责方 |
| --- | --- | --- |
| 确定性基底 | 自然地形、房屋、树、自然设施、箱子初始物品 | 服务端生成；浏览器仅重建可见的静态外观 |
| 权威差分 | 被采集对象的删除标记、玩家建筑、容器内容、燃料、弹药等变化 | 服务端结算并事务保存 |
| 动态状态 | 玩家、怪物、子弹、掉落物、坐姿、燃烧及拆除状态 | 服务端模拟；客户端预测或插值显示 |

相同种子只能推导初始状态，不能替代实际存档。开过的箱子、拆掉的树、已经消耗的机枪弹药不会被本地缓存恢复。浏览器也不能通过提交一份地图差分来创建物品或修改交易结果。

## 种子与独立随机流

先把参数转成字符串，以无空白的UTF-8 JSON数组编码，再计算MD5。数组编码和域标签避免负坐标、相邻数字与字符串拼接产生歧义；MD5只用于确定性随机种子与缓存校验，不用于口令保护。

```text
chunk_seed = MD5([world_seed, "chunk", chunk_x, chunk_y])
cell_seed  = MD5([chunk_seed, "tile", tile_x, tile_y])
event_seed = MD5([world_seed, "simulation", tick_number, system, entity_id])
```

区块类型和房屋布局使用区块流；树和箱子内容使用格子流；各机器、稀有物品和物品打乱各有命名子流。伪随机数使用固定32位整数运算的sfc32，Python与JavaScript采用相同的初始化、预热和抽取顺序。世界种子通过协议传为十进制字符串，不经过JavaScript浮点整数转换。

生成顺序、另一名玩家探索哪块区域，以及其他物品是否抽中，都不改变某格的初始状态。模拟随机流按逻辑帧、系统及实体分离；帧号随正常存档保存，不逐帧写数据库。浏览器显示帧号不参与权威模拟，网络重连也不重放过去的随机事件。

## 生成配置与旧世界

存档保留每个已生成区块的`chunk_versions`和对应的`generation_profiles`，配置记录算法标识、独立生成概率、初始次数、机器定义与配置摘要。改变生成内容时递增`TERRAIN_VERSION`；未探索区块使用当前配置，已有区块继续使用自己的配置。

基础枪械组的每箱概率保存在生成配置的`chest_gun_chance`中，新配置为20%；缺少该字段的旧配置仍按原始10%重建，不套用新概率。枪械组内部手枪、霰弹枪、步枪的比例保持70∶20∶10，稀有物品继续使用各自独立随机流。调整概率只影响尚未生成的区块，已开过或取空的箱子不会补货。

指南针使用格子种子下的独立`loot/compass`流，每个新自然箱子有2%概率出现；不改变其他物品的抽中判定。旧区块按原配置重建，不补发指南针。

## 客户端指南针导航

![指南针](../../cold_world_game/static/assets/compass.png)

登录消息中的`navigation_config`提供字符串世界种子、区块尺寸、类型算法及旧生成器区块的类型表，与是否启用地形差分无关。旧类型仅在服务器加载世界后推导并缓存，登录时发送一次；已生成区块类型不受玩家拆建影响。共享算法区块及尚未生成的区块由浏览器按种子推导类型，不请求生成服务端区块，也不计算建筑布局或箱内物品。

持有指南针时才启动独立Worker，以4ms工作片段扫描附近区块类型，并限制类型缓存为4096项。主线程至多每100ms筛选一次很小的建筑候选表，使用本地显示位置和真实Canvas视口；排除整个区块与画面相交的候选，再按外向半平面与欧氏距离选择。非零向量的单位向量点积符号与未归一化点积相同，因此不需要反复开平方。在原点处外向方向未定义，约定不限制方向。

搜索区域之外的区块中心最小可能距离必须严格大于当前候选距离，否则扩大搜索后再确定目标，不以固定搜索半径猜测最近建筑。同距按坐标稳定选择。多个指南针共用一个目标和CSS旋转值，针尖与表盘分别使用预加载PNG；不逐格逐帧寻路或创建Canvas。没有持有、页面隐藏或断线时不刷新方向，搜索中指针变暗。切换世界、重连或退出会清理旧Worker与请求，避免旧结果污染新世界。

生成算法是存档协议的一部分。改变布局算法、命名流、坐标编码或抽取顺序时，必须保留已有算法实现并新增算法标识，不能原地修改旧算法的结果。新增物品概率及初始次数只进入新配置，不能覆盖存档内旧配置。

无法按当前共享算法重建的旧区块保留完整原始记录，不猜测其初始地形，也不迁移成可能错误的默认地图。它们首次进入视野时传一次完整静态外观，之后仍使用增删差分。缺少区块标记的旧存档按兼容缺省值处理，不重建旧区块。

## 稀疏保存与事务

可重建区块的未改变自然对象不占`structure:*`记录。自然对象首次变化时保存完整当前对象；被采集时保存删除标记；玩家放置对象保存完整记录。对象完全恢复初始状态时可删除对应覆盖记录。区块清单和生成配置仍需保存，避免把已探索的区域误当作未探索区域重新抽取。

箱子物品、背包、地面、燃料、共享金币等仍在同一个SQLite事务内提交；失败时一起回滚。这里的差分是相对于确定性基底的**当前覆盖状态**，不是必须从头重放的无限事件日志。已有整图和分区存档继续兼容，备份方式见[服务器手册](../server/server.md#备份与更新)。

启动时服务端仍会重建已生成区域的运行时对象，用于碰撞、容器与怪物模拟，并在生成或读取时记录基底外观校验值与自然对象ID索引。订阅区块不再为计算校验值重复生成房屋和箱内物品。本方案减少数据库体积和重复序列化，并不等于服务端完全不计算地图，也不等于已经实现无限地图的内存卸载。

## 浏览器生成与缓存

浏览器在模块Web Worker内生成附近区块，不在渲染主线程批量计算地图。仅缓存静态外观，不缓存权威箱子物品。IndexedDB按配置摘要、世界种子和区块坐标保存最多512份基底；内存只保留附近订阅区块，离开范围后释放。缓存是可丢弃的加速层，不是存档。

服务端提供初始外观校验值，浏览器校验缓存和新生成结果，再叠加服务端覆盖。服务端会话标识隔离重连前后的修订号；后台生成完成时检查订阅代次，丢弃已离开区域或旧连接的结果。尚未就绪的区块暂不参与本机落脚判断，不在空白地图中继续跑。

没有Worker、存储权限不足或IndexedDB失败时不影响存档；缓存写入失败可以重新生成。算法不支持、校验不一致或Worker故障时重新连接并回退到服务端地图协议，不能带着错误地形继续游戏。

## 修订与增量同步

每名玩家订阅所在区块附近5×5范围。首次进入发送区块版本、修订、基底校验值和覆盖；保持订阅期间只发新增与删除。每区块保留有限的近期修改记录，客户端落后太远时发送该区块当前覆盖状态，而不是重放整张地图。

火光、机枪弹药、占座及怪物拆除标记走独立动态字段，不重新生成静态地形，也不重建全部碰撞索引。正常玩家和怪物快照仍需发送，地图差分不会自动消除战斗模拟、SQLite提交、音效、绘制或实体数量带来的全部开销。性能收益和测试边界见[实时性与性能](performance.md)。

## 维护入口与验证

| 文件 | 职责 |
| --- | --- |
| `cold_world_game/procedural.py` | 种子编码、固定随机流、生成配置、确定性对象及物品ID |
| `cold_world_game/terrain_stream.py` | 基底缓存、持久覆盖、区块修订、订阅与静态外观差分 |
| `cold_world_game/storage.py` | 稀疏记录与事务提交、旧存档读取、完整快照规范化 |
| `cold_world_game/static/js/procedural.js` | 与Python一致的静态地形算法 |
| `cold_world_game/static/js/terrain-worker.js` | 后台生成、IndexedDB与校验 |
| `cold_world_game/static/js/terrain-cache.js` | 订阅基底、覆盖合并与异步结果隔离 |

验证至少覆盖大整数种子、中文字符串、负坐标、不同区块生成顺序、前后端外观一致、缓存冷启动/命中/损坏、订阅期间连续增删、重连与旧客户端回退。同时验证自然对象删除、容器取放、容量不足、真实SQLite保存失败、旧区域不变、未探索区块使用当前配置，以及保存重启不重复生成。多人负载不能只测空地图或只测接口平均耗时。
